1. **P1 — The narrator secrecy guarantee does not match generation.** [C §6:156](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:156) promises hidden facts never reach narration. But `generation.ts:3633` accepts GM prose directly, and `3712` continues the entire GM conversation. `stripHiddenLoreContent` (`ai_staged.ts:78`) removes marked spans, not secrets paraphrased in reasoning, plans or tool arguments; rewrites also reuse that conversation (`observer.ts:985`). **Fix:** specify a separate, allowlisted narration context, including permitted mechanical outcomes, and apply it to initial narration and rewrites. Explicitly resolve the inline-GM-prose path.

2. **P1 — Timer migration can reverse progress or reject saves.** [C §4:109](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:109) says “same count,” but timers count **remaining** ticks downward (`structs.ts:504`); clocks fill upward. Existing totals are unrestricted, unlike 4/6/8 segments. **Fix:** preserve legacy capacities, map `filled = totalTicks − currentTicks`, retain IDs/status/visibility, and make migration idempotent. Specify every `manage_timer` action’s translation, including cancel and trigger.

3. **P1 — The proposed beat aliases are not equivalent.** [C §7:177](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:177) aliases three tools to `set_beat`. Currently, side beats pause and later resume the main beat (`toolExecutor.ts:762,830`); `advance_plan` separately completes and writes (`899,919`). **Fix:** retain legacy execution when no campaign record exists; otherwise define explicit completion and suspended-main-beat state. Do not infer structured beats from arbitrary prose.

4. **P1 — Rules checks lack causal facts and could demand incorrect mutations.** [J §2:42](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/judge-layer-v2-design.md:42): Fantastic Realms’ damage instruction is conditional—“If this struck a foe”—and its result has no target (`fantastic-realms-design:gmExecutor.ts:726,6702`). Burning a feat during the current roll is legitimate. Blood & Bone permits Exposure/Heat changes from fictional events without a named move (`systems/blood-and-bone/core.ts:64`). Meters clamp rather than refuse overflow (`metersAndTracks.ts:188`). **Fix:** declare checkable event contracts with target IDs and causal result IDs; leave unsupported semantic judgments advisory.

5. **P1 — Setup requirements contradict themselves and need coordinated replacement.** [C §§5,8:138](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:138) says missing expected parts never block; line 200 blocks starting on exactly that condition. Also, `campaign` already exists as an interview tag, quick mode requires `tone`, approval hashes only notes, and campaign-tool writes would not count as setup progress (`setupSteps.ts:34,63`; `campaignPlan.ts:277`; `generation.ts:3144`). **Fix:** distinguish minimal start requirements from warnings; specify quick/full coverage, tag migration, record hashing, card projection and progress detection together.

6. **P1 — Player-visible judge evidence can violate both secrecy and decision 235.** [J §6:133](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/judge-layer-v2-design.md:133) displays every flag’s quote, including removed secret leaks; pacing flags also conflict with “GM only.” C §10 prohibits revealing those secrets. **Fix:** separate private findings from public notices. Give `buildPlayerView` (`party/partyHost.ts:830`) an explicit public campaign projection—never campaign objects containing nested truths, doom text or hidden links.

7. **P1 — Holding output and background flag-only behavior are prerequisites, not current facts.** [J §8:176](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/judge-layer-v2-design.md:176) says background already only flags. Current code can rewrite there (`generation.ts:1738`), and prose callbacks run before judging (`3667`). **Fix:** make decision 221’s implementation an explicit dependency covering inline narration, continuation, TTS and party delivery; test that no background path rewrites.

8. **P2 — The record’s identity and persistence contract is missing.** [C §§3,11:69](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:69) leaves IDs, references, versioning and ownership unspecified. Sync carries blobs, but Designer conversions explicitly reconstruct fields (`designer_executor.ts:584,635`) and would discard an unhandled campaign. **Fix:** define versioned shapes, stable NPC/note/clock references, dangling-link handling, conversion round trips, and migration precedence. State that sync remains whole-story conflict resolution.

9. **P2 — Clock execution requires rules beyond “once per trigger.”** [C §4:97](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:97) omits portent thresholds, activation scope, newly created clocks, manual-plus-automatic ticking, and untick/refill behavior. `selectDirectorMove` still targets timers (`mythic.ts:656`). **Fix:** define ordered successful events, per-turn deduplication, persistent crossing notifications and director integration. Emit ticks early enough for narration, without ticking failed or repeated operations.

10. **P2 — “Deterministic” detection overclaims existing capabilities.** [J §§2–3:47](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/judge-layer-v2-design.md:47): M2 checks marked combat/challenge/high-stakes scenes, not arbitrary uncertain outcomes (`generation.ts:3373`). NPCs lack canonical location/ownership, and sheets are freeform (`structs.ts:437`; `observer.ts:548`). **Fix:** define facts with provenance and pre/post-turn timing; distinguish heuristics from verified violations. Add the missing keyword/key-phrase fields to C’s schema.

11. **P2 — Re-ask, confirmation and rewrite contracts remain unspecified.** [J §§2–4:49](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/judge-layer-v2-design.md:49) needs a keyed combined JSON schema, malformed/missing-result handling, fact IDs, agreement criteria and multi-finding priority. Existing validation checks format, not factual repair (`observer.ts:1063`). **Fix:** define these contracts, total correction budget, insufficient-round behavior and rejection/replacement of superseded prose; preserve already executed dice/state. Revalidate corrections before release.

12. **P2 — Prompt/tool/cost bounds need executable definitions.** [C §§6–7:144](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:144): “each clock,” secret and local person cannot remain within 800 tokens without selection rules. Keep schemas stable across setup/play and per-turn text in the live block. J §3 must budget tokens and latency for judging, confirmation, rewriting and regenerated choices—not merely count calls.

13. **P2 — Progress and post-setup maintenance are undefined.** [C §§7,12:252](C:/Users/Nikolas/Documents/GitHub/your-story/.claude/worktrees/repo-health-check-13aa7a/docs/campaign-format-design.md:252): front completion is not campaign completion, especially in an endless sandbox; `storyProgress` also supports chapter-bearing old saves (`mythic.ts:384`). Setup-only editing prevents changing wants or adding new threats. **Fix:** retain legacy progress, define style-specific pacing signals, and permit validated GM maintenance during play. Keep safety checks active despite ordinary observer suspension during setup (`observer.ts:725`).
